# Data Set

The data set is a collection of NRRD files used to test the projection algorithm.
It combines real data, synthetic data with known expected results, and invalid
files for error handling.

| ID | File | Size | Type | Purpose |
|----|------|------|------|---------|
| D1 | MRHead.nrrd (3D Slicer sample) | original | 16-bit | Visual check on real-world MRI data. Run with `data-CSV/head.csv` |
| D2 | tree_trunk.nrrd | 100x100x100 | 8-bit | "Tree trunk": value depends on distance from the central axis. A cross-section must show concentric circles, a lengthwise section must show stripes |
| D3 | random volume, made in memory | 500x500x500 | 8-bit | Performance test (at least 30 fps), see `scripts/benchmark.py` |
| D4 | constant volume, made inside the test | any | any | All voxels equal (min = max): tests division by zero (`tests/test_intensity.py`) |
| D5 | invalid input, made inside the tests | n/a | n/a | Missing file and a 2D file: tests the error message (`tests/test_volume_loader.py`) |
| D6 | tree_trunk_slicer.nrrd | 100x100x100 | 16-bit | Same idea as D2 with 16-bit values (0-3400), a thinner top and two branches, so every layer looks different, and a 3D Slicer header (orientation, mm, origin): tests 16-bit support and normalization, and opens in 3D Slicer |

## Notes
- The small synthetic files (D2, D6) are generated by a script (`scripts/dataset.py`) and are
  stored in `data-NRRD/`. The large volume (D3, 500^3, about 125MB) is not saved as a file: the
  benchmark creates it in memory when it runs.
- The MRI file (D1) is the 3D Slicer sample data, and it is stored in `data-NRRD/`.
- D4 and D5 are small and are created inside the tests, so there is no file for them.
- 8-bit (D2), 16-bit (D1, D6) are covered. A 32-bit file can be added later if needed.
